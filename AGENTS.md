# AGENTS.md

This repository is **kit**. The specification lives in `docs/` only: read it before changing code.
Code comments are not a contract — do not infer behaviour from them, and never let a comment
override the specification.

Two tiers of code: the **core** is the root Go module — the default `go build ./...` from the repository root builds only it, with no native libraries and no ONNX runtime, and only pure-Go modules (YAML, `golang.org/x/text`, two JSON Schema libraries). The optional packages (`mcp`, `webfetch`, `flow`, `eval`, `kittest`, `cmd`, `demo`, `scripts`) are separate Go modules of the same repository (`D85`); `rerank` stays in the core because the façade imports it (`D84`). The ML layer is opt-in: `guard/gliner` is L2 detection behind `//go:build ort`, and `kit.Config.GuardL2` must be set explicitly — pass `guard.L1Only()` to run L1-only on purpose (`D80`).

## Read order

1. `docs/README.md` — index and "where to look".
2. `docs/internals/design.md` — the frozen contracts: invariants `I-01`…`I-22`, package contracts, decisions `D21`…`D30`, and §5, the API changelist.
3. `docs/internals/architecture.md` — package layout and dependency rules; do not violate them.
4. `docs/internals/business-rules.md` — the BR-xx rules your change must keep true.
5. `docs/internals/plan.md` — current stage and Definition of Done.

`docs/guides/` is the how-to layer — task recipes (providers, structured output, tool calling, guardrails, retrieval, observability, eval, pipelines, errors, deployment, performance, security). `docs/concepts/` is the explanation layer, and `docs/reference/` is the lookup layer; see `docs/guides/README.md` for the Diátaxis split.

## Rules

- If code and docs disagree, fix the docs in the same change.
- Every operation goes through `internal/call` (`authz → guard → span → fn`). Never add user-facing middleware or bypass the policy.
- `authz`, `guard`, `model`, `embed`, `chunk`, `store`, `trace` must not import each other (`docs/internals/architecture.md`); the only permitted core-to-core edge is `trace → store`. `eval` imports `trace` and `internal/**` only and never `kit`. The core (the `kit` façade, `internal/**` and the seven subsystems) must not import the optional packages (`mcp`, `webfetch`, `flow`, `eval`, `kittest`, `rerank`, `cmd`, `demo`, `scripts`); the only recorded edge is `kit → rerank` (`D84`), enforced by the stdlib-only test `internal/importrules` (`core-no-optional`; a core _test_ may still import an optional package). The family rules are enforced by the same test (run in the core module, it walks the whole tree including the submodules) and by the `depguard` rules in `.golangci.yml` (run in every module; their patterns are module-relative, so the cross-module boundary lives in `internal/importrules` alone).
- The default build (`go build ./...`) must not require native libraries; ONNX/ORT code goes behind `//go:build ort`.
- Detection does not depend on the rail; the rail only affects the decision table (`docs/internals/design.md`, `I-02`).
- Traces carry masked text by default (`Config.TraceText`, `trace.TextMasked`); never log or persist raw message text.
- Tests use the standard library only. Validate the core with `go build ./... && go vet ./... && go test ./...`; validate every module with `make check`, which runs build, `vet`, tests, `gofumpt` and `golangci-lint` for the core and for each of `mcp`, `webfetch`, `flow`, `eval`, `kittest`, `cmd`, `demo`, `scripts`.
- Exported API in published packages carries a godoc comment (`internal/apidoc` enforces it); a comment is still not a contract — `docs/` is (`BR-75`).
