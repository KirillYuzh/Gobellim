# Решения и допущения

Страница фиксирует границы v1, журнал принятых решений и допущения, которые
ещё предстоит проверить. Журнал решений ведётся в формате ADR: каждое решение
хранит обоснование и отвергнутую альтернативу.

## Границы v1

**Входит:** локальные и API LLM (vLLM, Ollama, OpenAI-compatible, GigaChat);
локальные (ONNX под тегом `ort`) и удалённые эмбеддинги; токенный чанкер;
ingest и гибридный поиск в ES (BM25 + kNN, RRF в Go); RBAC в YAML; guard с
одной моделью gliner-guard-omni и детерминированным слоем; tool calling с
вычитанием запрещённых tools и эффектами инструмента (egress, approval),
именованные хуки (`BeforeToolCall`/`AfterToolCall`); типизированные
последовательные пайплайны `flow` с suspend/resume; SSRF-защищённый инструмент
`webfetch`; бюджет хода; трейсинг в ES по модели Langfuse с сэмплированием и явной
политикой текста; детерминированные eval-проверки трейсов; дашборды Grafana.

**Не входит:** стриминг; мультиагентность; workflows как граф/builder-DSL
(типизированные последовательные `flow`-пайплайны входят, `D31` — сужение); ABAC;
UI для трейсов; JSON-API чтения трейсов (запланировано, не реализовано); несколько
хранилищ; удалённый guard; GPU-провайдеры ORT; обратимая анонимизация PII; Colang и
диалоговые рельсы.

### Продолжение журнала: D21…D35

Решения D21…D30 живут в [Дизайне v1](./design.md) §4 и здесь не дублируются.
Они покрывают контракт ES-запроса (D21), guard-таблицу и каноникализацию (D22),
политику текста трейса (D23), sampling (D24), эгресс и Rule of Two (D25),
ошибку инструмента как результат (D26), версионирование guard (D27), разделение
L1/L2 по семантике и структуре (D28), `SchemaMode` (D29) и пакет `eval` (D30).

Решения D31…D35 ниже — сознательные сдвиги границ v1. Они не переписывают D1…D30.

## Что нового (TRIZ, SIT, SCAMPER)

Три идеи, на которых сошлись все три метода (Merging/Universality, Task
Unification, Combine; Prior Action, Subtraction, Eliminate; Prior Action,
Attribute Dependency, Adapt):

1. **Единый примитив вызова** вместо пользовательских middleware: authz, guard
   и трейс неотделимы от вызова LLM, tool, эмбеддера и ES.
2. **Вычитание tools из схемы модели** плюс повторная проверка при исполнении.
3. **ACL при записи + фильтр принципала внутри kNN** (аналог row-level
   security).

Проверка prior art ограничена: поиск по доступным публичным источникам показал
близкие по духу проекты на Go (galdor, Eino, langchaingo), но связки «RBAC в
YAML + только ES + локальный guard + трейсы в той же ES» не нашёл. Это не
юридическое заключение о новизне; для патентных целей нужен профессиональный
поиск.
