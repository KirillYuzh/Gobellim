# Бизнес-правила

Правила, которые изменение кода обязано сохранять. Каждое правило
пронумеровано (`BR-xx`); ID не переименовываются и не перенумеровываются.
Правило без пометки о слое действует в детерминированном слое.

Таблица sentinel-ошибок живёт в [Ошибках](../reference/errors.md), значения по
умолчанию и лимиты — в [Конфигурации](../reference/configuration.md).

Метки в колонке «Источник»: `архитектура` — [Архитектура](./architecture.md),
`решения` — [Решения и допущения](./decisions.md), `demo` —
[demo](../../demo/README.ru.md).

## Принципы

- **Один примитив вызова.** Любой вызов LLM, tool, эмбеддера и ES идёт через
  `internal/call`: `authz → guard → span → fn`. Пользователь middleware не
  пишет, обойти политику нельзя (D1).
- **Deny-by-default.** Нет явного разрешения — операция отклоняется. Это
  касается и RBAC, и ACL при поиске (D3, D4).
- **Детерминированный слой раньше ML.** RBAC, валидация аргументов, ACL и
  лимиты не зависят от модели; рельсы, оценённые моделью, обходимы (D4, D5,
  архитектура).
- **Маскирование PII необратимо.** Модель видит заглушки вида `[PII:SNILS]` и
  не может использовать реальные значения в аргументах tools (архитектура).
- **Fail-closed.** Недоступность guard — это отказ операции
  (`ErrGuardUnavailable`), а не пропуск (архитектура, строка DoS).
- **Одна БД и один guard.** Только ES (D11, D11); одна guard-модель за
  интерфейсом `guard.Detector` (D6).

Цепочка расширяется пакетными функциями `Then`/`Chain`/`Chain3`, потому что метод в Go не может объявить собственные параметры типа.                                                                                                                                                                                                                                                                                                                   | детерминированный      | D31                  |
| BR-67 | `flow` suspend/resume: шаг останавливается через `flow.Suspend(payload)`; `Result.Snapshot` (JSON: `state`, `step_index`, `step_input`, `steps`) — единственный артефакт, нужный `Resume`, а payload продолжения валидируется по схеме типа `Resume` и передаётся в `onResume`. Ветвлений, параллелизма, foreach и циклов в `flow` сознательно нет (D31).                                                                                                                                                                                                                                                                                                                | детерминированный      | D31                  |
| BR-68 | Egress — свойство инструмента: `Effects(EffectEgress)` + host-allowlist по аргументам (`EgressHosts`, совпадение по границе домена) и «Rule of Two» проверяет рантайм; отказ — `ErrUnauthorized`. Встроенный `webfetch.New` регистрируется именно так, поэтому рантаймовые правила применимы и к нему.                                                                                                                                                                                                                                                                                                                                                                   | детерминированный      | I-10, D25, D33       |
| BR-69 | `webfetch` — SSRF-защищённый фетч: только схемы `http`/`https`; резолвнутые адреса проверяются внутри dialer'а (loopback, RFC 1918 / ULA, link-local, unspecified, multicast, CGNAT `100.64.0.0/10`, IPv4-mapped), поэтому редиректы и DNS-rebinding покрыты; есть потолок редиректов и потолок тела (`Out.Truncated`); не-2xx — это данные, а не ошибка; прокси принудительно выключен.                                                                                                                                                                                                                                                                                 | детерминированный      | D33                  |
| BR-70 | У L2 есть потолок токенов (`gliner.Config.MaxTokens`, по умолчанию `DefaultMaxTokens` = 512, клампится до `max_sequence_length` модели); слова за потолком отбрасываются целиком, поэтому хвост входа размечает только L1 — тот же класс ограничения, что и I-06.                                                                                                                                                                                                                                                                                                                                                                                                        | ML                     | I-06, D34            |
| BR-71 | Go-сторона L2 поддерживает любую таксономию `config.json`: N групп классификации, у каждой своё имя `output`, `multi_label` + `sigmoid`, пороги на метку/группу (`thresholds`) и общий `category_map`. Это одна модель за `guard.Detector`, поэтому богатый экспорт заменяет компактный без правок кода (D28, D35).                                                                                                                                                                                                                                                                                                                                                      | ML                     | D28, D35             |
| BR-72 | Подавление находки L2 — только явное: значение `SAFE` в `category_map` или вхождение метки во встроенный список безопасных имён; незнакомая, немаппленная метка fail-safe → `UNSAFE` (I-14). `category_map` принимает значения `PII`/`SECRET`/`INJECTION`/`UNSAFE`/`SAFE`.                                                                                                                                                                                                                                                                                                                                                                                               | ML                     | I-14, D35            |
| BR-73 | `cmd/kitctl verify` — гейты эксплуатации: `window` (I-06), `models` (структура guard/embed), `parity` (паритет guard, требует `-tags ort`), `latency` (замер L1 и L1+L2). Подкоманды принимают флаги до и после позиционных аргументов.                                                                                                                                                                                                                                                                                                                                                                                                                                  | детерминированный      | архитектура          |
| BR-74 | Правила импортов проверяются двумя способами: stdlib-only тест `internal/importrules` (в `go test ./...`) и правила `depguard` в `.golangci.yml` (в `make check` и в CI-джобе `lint`).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   | детерминированный      | I-13                 |
| BR-75 | Спецификация живёт в `docs/`; комментарии в коде — не контракт и источником поведения не являются. Объяснительных комментариев в `.go`-файлах нет — остаются только функциональные директивы (`//go:build`, `//go:embed`, `//go:generate`, `//nolint` и т. п.), поэтому ни наличие, ни отсутствие комментария ни на что не опирается.                                                                                                                                                                                                                                                                                                                                    | —                      | архитектура          |

## Потоки

### Chat

1. Создать trace, получить принципала из `context.Context` (BR-40, BR-07).
2. Собрать историю: оставить только роли `user`/`assistant`, отбросить
   `tool_calls` и клиентские роли `system`/`tool` (BR-30).
3. Guard rail `input` по каждому сообщению: детерминированный слой → L2
   (BR-24…BR-27). Reject → `ErrGuardReject` без вызова модели (BR-25); PII →
   необратимая маска (BR-04). Любая маска или находка помечает ход как
   «видевший недоверенный ввод» для Rule of Two (BR-51).
4. Вычислить доступные tools по роли через `authz` и вычесть запрещённые из
   схемы, передаваемой модели (BR-09, BR-16).
5. Цикл «модель → tools → модель», пока `steps < max_steps` (BR-20): вызвать
   модель (observation GENERATION); на последнем шаге `tool_choice` = `none`,
   чтобы модель отвечала, а не открывала вызов, который уже не исполнится. При
   `tool_calls` для каждого вызова — повторная проверка прав (BR-17), валидация
   args (BR-18, BR-19), лимиты `max_calls`/таймаут (BR-21, BR-22), approval по
   fingerprint (BR-53, BR-63), egress-политика (BR-51, BR-68), before-хук (BR-61),
   исполнение, after-хук (BR-61), guard результата — последним (BR-32, BR-62),
   `ValidateOutput`/`ModelView`, один ретрай при невалидных args (BR-23); результат
   добавить в контекст. Ошибка инструмента возвращается модели как результат
   (BR-50). Суммарные токены хода сверяются с `MaxTotalTokens` (BR-52).
6. Guard rail `output`: PII и секреты маскируются; INJECTION/UNSAFE
   записываются действием `Detect` без изменения текста (BR-56, rail output).
7. Завершить trace: trace и observations уходят в очередь асинхронного писателя
   (BR-42, BR-44).
8. Вернуть полный ответ, без стриминга (BR-45).

### Ingest

1. Создать trace, получить принципала; `Tenant` обязателен (BR-40, BR-07, BR-49).
2. Чанкование документа по токенам с overlap (BR-36).
3. Вычислить ACL при записи (tenant + roles, заданные вызывающим) и записать в
   каждый чанк (BR-10, BR-11, BR-14); посчитать эмбеддинги через `Passages()`
   (BR-34).
4. Guard: каждый чанк проходит guard; отклонённый пишется маркером
   `quarantined: true` без текста и вектора (BR-31, BR-05).
5. Удалить прежние чанки документа (`_delete_by_query` по `doc_id` + `tenant`):
   повторная индексация не должна оставлять хвосты.
6. Проверить размерность векторов и записать чанки в ES через `internal/call`
   (BR-01, BR-38).

### Search

1. Создать trace, получить принципала; `Tenant` обязателен (BR-40, BR-07, BR-49).
2. Эмбеддить запрос через `Query()` с обязательным префиксом (BR-34).
3. Построить kNN-запрос и BM25-запрос, каждый с ACL-фильтром принципала
   (tenant + roles), `quarantined: false` и необязательным фильтром метаданных
   `store.Filter`; deny-by-default (BR-12, BR-13, BR-57).
4. Выполнить оба запроса через `_msearch` и слить результаты алгоритмом RRF в
   Go (BR-37).
5. Вернуть top-k (BR-39).

## Матрица решений guard по rail

Пять рельсов (без dialog): `input`, `retrieval`, `execution`, `output`, `tool_result`.

| Rail          | Детерминированный слой                                                                                     | ML-слой (L2)                                                                                             | Действие                                                                                                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `input`       | L0/L1: фразы, regex, контрольные суммы RU PII; каноникализация и decode-and-rescan (BR-55)                 | метки классификации (`safety`/таксономия) → `UNSAFE`/`INJECTION`; метки сущностей → `PII` (BR-27, BR-71) | INJECTION/UNSAFE → reject (`ErrGuardReject`); PII/SECRET → mask необратимо; иначе allow                                                                                                  |
| `retrieval`   | ACL-фильтр tenant + roles и `quarantined: false` внутри kNN и BM25; фильтр `store.Filter`; deny-by-default | карантин чанков при ingest (маркер `quarantined: true`)                                                  | чанк вне ACL или карантинный не возвращается; отклонённый чанк ложится в индекс маркером                                                                                                 |
| `execution`   | RBAC, JSON Schema со `additionalProperties:false`, лимиты args/steps/calls/timeout; ML не используется     | —                                                                                                        | нет прав → `ErrUnauthorized` (фатально); неизвестный tool, невалидные или большие args, `max_calls` и ошибка инструмента → результат-ошибка модели; исчерпан `max_steps` → `ErrMaxSteps` |
| `output`      | правила маскирования секретов и PII                                                                        | PII → mask; INJECTION/UNSAFE → `Detect` (запись находки, текст не меняется)                              | PII/SECRET → mask; инъекция/unsafe → `Detect`; иначе allow                                                                                                                               |
| `tool_result` | результаты tools проверяются как `input` (fast-fail на инъекциях)                                          | —                                                                                                        | reject → результат заменяется на `{"error":"result blocked by guard"}`; PII/секреты → mask                                                                                               |
