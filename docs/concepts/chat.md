# Chat

Chat — одна операция. Она собирает историю, проверяет её guard'ом, выбирает
инструменты, доступные вызывающему, и крутит цикл «модель → инструмент → модель»,
пока модель не вернёт финальный ответ.

Операция идёт через единый примитив вызова: проверка прав, guard, span трейса,
выполнение. Второй точки входа нет, поэтому проверку нельзя обойти.

## Когда использовать

- Задача открытая, шаги заранее не известны. Модель сама решает, какой инструмент
  вызвать, сколько раз и когда остановиться.
- Ответ нужен по вашим документам и с вызовом внешних API в одном запросе.
- Модель должна отвечать от имени конкретного пользователя, с его ролями.

Для фиксированного сценария вызывайте операции напрямую — `Ingest`, `Search`,
`Delete`. Мультиагентности в v1 нет; для детерминированного многошагового процесса есть
пакет `flow` — типизированные последовательные шаги с suspend/resume
([Пайплайны](./flow.md)).

## Быстрый старт

```go
app, err := kit.New(ctx, kit.Config{
	ES:     es,     // ваш клиент Elasticsearch
	LLM:    llm,    // vLLM, Ollama, OpenAI-совместимый API или GigaChat
	Policy: policy, // authz.Load("policy.yaml")
})
if err != nil {
	return err
}
if err := app.Setup(ctx); err != nil { // один раз создаёт индексы
	return err
}

ctx = kit.WithPrincipal(ctx, kit.Principal{
	UserID: "u-1",
	Roles:  []string{"user"},
	Tenant: "acme",
})

answer, err := app.Chat(ctx, kit.ChatRequest{
	System:   "Ты ассистент поддержки. Отвечай кратко.",
	Messages: []model.Message{{Role: model.RoleUser, Content: "Какая погода в Москве?"}},
})
```

`kit.WithPrincipal` кладёт принципала в контекст. Без принципала операция вернёт
`ErrUnauthorized`. `Chat` требует права `chat`. Системный промпт задаёт только
приложение — в поле `System`.

## Как использовать

### История сообщений

В модель уходят только сообщения с ролями `user` и `assistant`. Клиентские роли
`system` и `tool` отбрасываются, `tool_calls` тоже. Каждое оставшееся сообщение
проходит guard входа.

Это защита от подделки истории клиентом: инструкции приложения нельзя перебить
сообщением из запроса.

### Память

Если задан `ChatRequest.ThreadID`, `Chat` сам работает с памятью: перед ходом
подгружает последние `MemoryLimit` сообщений треда, а после успешного хода
дописывает сообщения хода и ответ. При `MemoryRecall > 0` и наличии `Embedder`
в системное сообщение добавляется блок семантического recall. Это требует права
`memory`. Без `ThreadID` поведение прежнее — историю собирает вызывающий.
Подробнее — [Память](./memory.md).

### Цикл инструментов

На шаге цикла модель либо отвечает, либо просит вызвать инструмент. Для каждого
запрошенного вызова kit:

1. проверяет права повторно — уже на исполнении;
2. валидирует аргументы по JSON Schema;
3. проходит approval (по fingerprint, один раз за ход) и egress-политику, если инструмент их требует;
4. вызывает before-хук (`BeforeToolCall`), затем функцию с таймаутом `ToolTimeout`;
5. вызывает after-хук (`AfterToolCall`), затем прогоняет результат через guard (`tool_result`) — **последним** — и, если включено, `ValidateOutput`, и показывает модели `ModelView`.

Ошибка инструмента не рушит ход: она возвращается модели результатом вида
`{"error": "..."}` (инвариант I-11), и модель может на неё среагировать.
Ход прерывают отказ авторизации (RBAC и эгресс-политика), недоступность провайдера,
инфраструктурные ошибки, отсутствие требуемого подтверждения (`ErrApprovalRequired`)
и исчерпание одного ретрая на невалидные аргументы (BR-23).

Цикл ограничен `MaxSteps` (по умолчанию 8); на последнем шаге `tool_choice`
принудительно выставляется в `"none"`, поэтому ход завершается финальным
ответом, а не ещё одним вызовом. При исчерпании возвращается `ErrMaxSteps`.

Бюджет хода задаёт `MaxTotalTokens`: превышение возвращает `ErrBudget`. Стоимость
операции библиотека считает, если задан `Config.Pricing` (см.
[Наблюдаемость](./observability.md)).

### Ответ целиком и стриминг

`Chat` буферизует ответ целиком: guard выхода должен видеть текст до отдачи.
Возвращается `Response`: `Message`, `Usage`, `TraceID` и `Decision` (версия guard,
хэш политики, признак недоверенности хода) — `Response` заполнен и при ошибке
(BR-103).
Для потока есть `ChatStream` — он прогоняет скользящее окно ответа (400 рун,
хвост 96 рун) через рельс `output` и отдаёт уже подтверждённые куски через
канал; отказ рельса даёт `Retract` и аборт потока. Если клиент LLM не реализует
`model.Streamer`, `ChatStream` откатывается на буферизованный `Chat`.
