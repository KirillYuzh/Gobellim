# Модель угроз и границы гарантий

Этот документ — объяснение: нормативные утверждения живут в
[Дизайне v1](../internals/design.md), [Бизнес-правилах](../internals/business-rules.md)
и [Решениях](../internals/decisions.md). Он отвечает на вопрос, **что библиотека
защищает, от чего и чего не обещает** — чтобы свойство не переоценили.

Как сообщить об уязвимости — [GitHub advisories](https://github.com/KirillYuzh/Gobellim/security/advisories/new)
(приватно, до выхода исправления).

## Что библиотека гарантирует

Гарантии держатся на **детерминированных** механизмах, а не на классификаторе:

- единый путь вызова `authz → guard → span → fn` — обойти политику нельзя
  (I-01);
- deny-by-default: RBAC на каждой операции и на каждом вызове инструмента;
- вычитание запрещённых инструментов из схемы **до** модели и повторная проверка
  при исполнении;
- эгресс-политика по аргументам и «Rule of Two» (I-10);
- недоверенность по происхождению: результат инструмента помечает ход, поэтому
  защита от эксфильтрации не обходится вторым шагом (I-22);
- лимиты и деньги (`max_steps`, `max_calls`, таймаут, `ArgsMaxBytes`, бюджет,
  rate limit) — часть контракта (I-09);
- PII маскируется необратимо для модели; вне `RegionRU` релаксация `AllowPII`
  недоступна (BR-106);
- аудит: трейсы маскируются по умолчанию, версия guard и хэш политики пишутся в
  каждый трейс (I-07, I-08); отказы RBAC и эгресса — security-события (BR-107).

ML-слой (L2) — **дополнительный** слой, а не граница доверия: L1 (правила) входит
в сборку по умолчанию, L2 — плагин.

## Модель угроз

| Актив       | Угроза                                                         | Детерминированный ответ                                                        | Слой |
| ----------- | -------------------------------------------------------------- | ------------------------------------------------------------------------------ | ---- |
| Права       | принципал вызывает операцию или инструмент, которых у него нет | RBAC на исполнении, deny-by-default                                            | ядро |
| Инструменты | модель вызывает запрещённый инструмент                         | инструмент вычтен из схемы заранее; вызов на исполнении отклонён и залогирован | ядро |
| Данные      | эксфильтрация через инструмент                                 | `Effects` инструмента, host-allowlist, Rule of Two                             | ядро |
| Промпт      | инструкции из недоверенных данных «моют» управляющий поток     | недоверенность по происхождению (I-22), spotlighting (I-18)                    | ядро |
| PII         | данные уходят провайдеру вне РФ                                | маскирование обязательно при `Region() != RegionRU` (BR-106)                   | ядро |
| Секреты     | сырой текст в логах и трейсах                                  | политика текста `masked` по умолчанию (I-07)                                   | ядро |
| Ресурсы     | один тенант выжигает бюджет                                    | лимиты, таймауты, бюджет хода, rate limit                                      | ядро |
| Изоляция    | поиск пересекает тенантов                                      | ACL-фильтр `tenant`+`roles` внутри запроса, deny-by-default                    | ядро |
| Модель      | инъекция через результат инструмента                           | второй слой L1/L2 + детерминированные правила выше                             | ML   |

## Non-goals (чего библиотека не делает)

- **Не обещает защиту от prompt injection.** Детекторы этого класса обходятся
  адаптивными атаками (перефразирование, другие языки, кодировки). Честная
  формулировка: библиотека **ограничивает влияние недоверенных данных на
  привилегированные действия** через policy-проверки, а детекторы — дополнение.
- **Не заменяет gateway.** AuthN (кто вызвал) — не её задача; принципал приходит
  из контекста.
- **Не хранит ваши данные.** Ядро не владеет хранилищем: ES/Kafka/PG приходят
  через порты (D10, `Config.ES` опционален).
- **Не гарантирует полноту детекции.** L1 — правила по структурированным ID;
  L2 — модель с известными обходами (см. model card). Не найденное — не значит
  отсутствующее.
- **Не обеспечивает изоляцию арендаторов за вас.** ACL-логика живёт в адаптере
  хранилища; ядро выдаёт фильтр, а корректность запроса — за портом.
- **Не поставляет удалённый guard.** Поставляемый ML-детектор — `guard/gliner`
  (`-tags ort`); `guard-remote` не реализован, удалённый сервис guard — вне
  границ v1 (D76).

## Границы доверия

- **Доверенное**: код вашего сервиса, `policy.yaml`, `Principal` из контекста,
  канонически замаскированный текст, `Config`.
- **Недоверенное**: текст пользователя (control flow, но может нести PII),
  результаты инструментов, retrieval, `webfetch`, MCP, memory-recall, ответ
  модели.
- Недоверенные данные **могут** попасть в промпт, но не могут напрямую стать
  аргументами привилегированного инструмента без policy/approval.
