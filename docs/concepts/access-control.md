# Доступ

kit разделяет два независимых механизма доступа. RBAC отвечает за то, какие
операции и инструменты доступны принципалу. ACL отвечает за то, какие документы
принципал видит в поиске.

Оба механизма детерминированные и отрабатывают до вызова модели.

## Когда использовать

- Сервис обслуживает несколько пользователей или тенантов, и им нужны разные
  права на операции и инструменты.
- Часть инструментов доступна только администраторам.
- Документы принадлежат разным подразделениям, и поиск не должен их смешивать.

Аутентификацию (AuthN) выполняет ваш сервис или gateway. kit не выдаёт токены и
не проверяет подписи — он получает уже готового принципала.

## Быстрый старт

`policy.yaml`

```yaml
version: 1
default: deny
roles:
  user:
    permissions:
      - tool:get_weather
  admin:
    permissions:
      - "*"
```

`main.go`

```go
policy, err := authz.Load("policy.yaml") // строгий разбор; ошибка → ErrInvalidConfig
if err != nil {
    return err
}

app, err := kit.New(ctx, kit.Config{ES: es, LLM: llm, Policy: policy})
if err != nil {
    return err
}

// AuthN делает ваш слой: проверьте токен и положите принципала в контекст.
ctx = kit.WithPrincipal(ctx, kit.Principal{
    UserID: "u-1",
    Roles:  []string{"user"},
    Tenant: "acme",
})

answer, err := app.Chat(ctx, kit.ChatRequest{
    Messages: []model.Message{{Role: model.RoleUser, Content: "Какая погода в Москве?"}},
})
```

## Как использовать

### Политика

`policy.yaml` — единственный источник прав. Разбор строгий: неизвестное поле
отклоняется (`KnownFields(true)`).

| Ключ                      | Значение     | Ограничение                                                                     |
| ------------------------- | ------------ | ------------------------------------------------------------------------------- |
| `version`                 | `1`          | другое значение → `ErrInvalidConfig`                                            |
| `default`                 | `deny`       | поддерживается только `deny`                                                    |
| `roles.<имя>.permissions` | список строк | `search`, `ingest`, `delete`, `generate`, `prune`, `trace`, `tool:<имя>`, `"*"` |

Политика проверяется при `kit.New`, а не при первом запросе: неверный
`policy.yaml` возвращает `ErrInvalidConfig`, и сервис не поднимается.

Право `"*"` в списке роли разрешает всё. Отсутствие права — отказ, потому что
действует deny-by-default.

Проверить файл без запуска сервиса: `kitctl policy check ./policy.yaml`.

### Принципал в контексте

`kit.Principal` передаётся через `context.Context`. Его кладёт `kit.WithPrincipal`,
читает `kit.PrincipalFrom`.

```go
type Principal struct {
    UserID string
    Roles  []string
    Tenant string
}
```

| Поле     | Роль в проверке                                        |
| -------- | ------------------------------------------------------ |
| `UserID` | идентификатор для трейсов и сообщений об отказе        |
| `Roles`  | по ним считается RBAC: роль → набор прав               |
| `Tenant` | ограничивает и запись, и поиск; попадает в каждый чанк |

Если принципала в контексте нет или он пуст, операция возвращает
`ErrUnauthorized`. Один принципал может иметь несколько ролей; достаточно, чтобы
право дала любая из них.

### Права на операции

| Операция      | Требуемое право | Область                              |
| ------------- | --------------- | ------------------------------------ |
| `Ingest`      | `ingest`        | нужен непустой `Tenant`              |
| `Search`      | `search`        | нужен непустой `Tenant`              |
| `Delete`      | `delete`        | нужен непустой `Tenant`              |
| `Prune`       | `prune`         | удаляет старые трейсы и observations |
| `Score`       | `trace`         | записывает оценку трейса             |
| `Generate[T]` | `generate`      | input/output guard, `ErrorStrategy`  |
| `Chat`        | — (см. ниже)    | права проверяются на инструменты     |

Операции над данными (`Ingest`, `Search`, `Delete`) требуют, чтобы у
принципала был непустой `Tenant`: пустой тенант вернул бы `ErrUnauthorized`,
потому что иначе область поиска и записи расширилась бы на все тенанты с той же
ролью. `Prune` тенант не требует: это глобальное действие эксплуатации по времени
(как ILM), поэтому ему достаточно принципала и права `prune`. `Chat` и `Generate`
тоже не тенант-скоупны.

`Chat` отдельного права не требует: права проверяются на каждый запрошенный
моделью инструмент. `Generate` — полноценная операция примитива со своими
input/output guard и правом `generate`.

### Права на инструменты

Инструмент, зарегистрированный через `kit.Tool`, по умолчанию требует право
`tool:<имя>`. Право переопределяется опцией `kit.Perm`.

Проверка идёт дважды. Сначала запрещённые инструменты вычитаются из списка,
который получает модель. Затем, при исполнении, право проверяется повторно —
решение принимает рантайм, а не модель.

> [!WARNING]
> Запрещённый инструмент не просто не выполняется — он не попадает в схему,
> которую видит модель. Модель не знает о его существовании и не может его
> запросить.

### ACL документов

ACL задаёт вызывающий в `kit.Doc.ACL` при `Ingest`. Это список ролей, которым
документ разрешён. Значение считается при записи и хранится в каждом чанке.

Поиск всегда добавляет фильтр принципала — `tenant` и `roles` — и в kNN-запрос,
и в BM25. Чанк без совпадения ACL не возвращается: deny-by-default. Пустой список
ролей даёт `"terms":{"acl":[]}`, что не совпадает ни с одним документом.

### Модель прав

Модель прав в v1 — роли плюс один атрибут `tenant`. ABAC, владельцы, иерархия и
наследование ролей не поддерживаются.
