# 02. Бизнес-логика

Источники: `00-README.md` (§3 границы, §4 журнал решений D1–D20, §6 допущения A1–A9), `01-architecture.md` (§2 правила зависимостей, §4 рантайм, §5 безопасность, §6 observability), `03-api-and-config.md` (сигнатуры и значения по умолчанию).

## 1. Область и принципы

- **Один примитив вызова.** Любой вызов LLM, tool, эмбеддера и ES идёт через `internal/call`: `authz → guard → span → fn`. Пользователь middleware не пишет, обойти политику нельзя (D1).
- **Deny-by-default.** Нет явного разрешения — операция отклоняется. Это касается и RBAC, и ACL при поиске (D3, D4).
- **Детерминированный слой раньше ML.** RBAC, валидация аргументов, ACL и лимиты не зависят от модели; рельсы, оценённые моделью, обходимы (D4, D5, 01 §5).
- **Маскирование PII необратимо.** Модель видит заглушки вида `[PII:SNILS]` и не может использовать реальные значения в аргументах tools (01 §5).
- **Fail-closed.** Недоступность guard — это отказ операции (`ErrGuardUnavailable`), а не пропуск (01 §5, строка DoS).
- **Одна БД и один guard.** Только ES (D11, D11); одна guard-модель за интерфейсом `guard.Detector` (D6).

## 3. Потоки

### 3.1 Chat

1. Создать trace, получить принципала из `context.Context` (BR-40, BR-07).
2. Собрать историю: оставить только роли `user`/`assistant`, отбросить `tool_calls` и клиентские роли `system`/`tool` (BR-30).
3. Guard rail `input`: L0 → L1 → L2 (BR-24…BR-27). Reject → `ErrGuardReject` без вызова модели (BR-25); PII → необратимая маска (BR-04).
4. Вычислить доступные tools по роли через `authz` и вычесть запрещённые из схемы, передаваемой модели (BR-09, BR-16).
5. Цикл «модель → tools → модель», пока `steps < max_steps` (BR-20): вызвать модель (observation GENERATION); при `tool_calls` для каждого вызова — повторная проверка прав (BR-17), валидация args (BR-18, BR-19), лимиты `max_calls`/таймаут (BR-21, BR-22), guard результата (BR-32), один ретрай при невалидных args (BR-23); результат добавить в контекст.
6. Guard rail `output`: маскировать секреты и PII (BR-27, rail output).
7. Завершить trace: trace и observations уходят в очередь асинхронного писателя (BR-42, BR-44).
8. Вернуть полный ответ, без стриминга (BR-45).

### 3.2 Ingest

1. Создать trace, получить принципала (BR-40, BR-07).
2. Чанкование документа по токенам с overlap (BR-36).
3. Вычислить ACL при записи: tenant + roles, заданные вызывающим, и записать в каждый чанк (BR-10, BR-11, BR-14).
4. Guard/карантин: каждый чанк проходит guard; отклонённый — в карантин и не индексируется (BR-31, BR-05).
5. Записать чанки в ES через `internal/call` (BR-01, BR-38).

### 3.3 Search

1. Создать trace, получить принципала (BR-40, BR-07).
2. Эмбеддить запрос через `Query()` с обязательным префиксом (BR-34).
3. Построить kNN-запрос и BM25-запрос, каждый с ACL-фильтром принципала (tenant + roles); deny-by-default (BR-12, BR-13).
4. Выполнить оба запроса через `_msearch` и слить результаты алгоритмом RRF в Go (BR-37).
5. Вернуть top-k (BR-39).

## 4. Матрица решений guard по rail

Четыре рельса без dialog (01 §5).

| Rail          | Детерминированный слой                                                                                 | ML-слой (L2)                                      | Действие                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `input`       | L0/L1: фразы, regex, контрольные суммы RU PII                                                          | safety, PII, атаки, вредный контент, intent, tone | атаки/unsafe → reject (`ErrGuardReject`); PII → mask необратимо; иначе allow                                                         |
| `retrieval`   | ACL-фильтр tenant + roles внутри kNN и BM25; deny-by-default                                           | карантин чанков при ingest                        | чанк вне ACL не возвращается; отклонённый чанк — в карантин                                                                          |
| `execution`   | RBAC, JSON Schema со `additionalProperties:false`, лимиты args/steps/calls/timeout; ML не используется | —                                                 | allow; нет прав → `ErrUnauthorized`; неизвестный tool → `ErrToolNotFound`; невалидные args → `ErrInvalidArgs`; лимит → `ErrMaxSteps` |
| `output`      | правила маскирования секретов и PII                                                                    | mask (та же модель)                               | найдено → mask; иначе allow                                                                                                          |
| `tool_result` | результаты tools проверяются как `input` (fast-fail на инъекциях)                                      | —                                                 | reject → результат заменяется на `[blocked by guard]`; PII/секреты → mask                                                            |

## 5. Ошибки

Sentinels объявлены в `errors.go` фасада (`kit`).

| Sentinel              | Когда возвращается                                                                                  | Что видит клиент                         |
| --------------------- | --------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| `ErrInvalidConfig`    | `New`: невалидный `policy.yaml` (строгий режим), схема tool, `kit_embedder.json`, конфиг провайдера | ошибка на старте, сервис не поднимается  |
| `ErrUnauthorized`     | `authz.Check` не даёт прав; нет принципала в ctx; отказ ACL                                         | 403 без деталей политики                 |
| `ErrToolNotFound`     | модель запросила tool, которого нет в схеме или который запрещён                                    | 400 с именем tool                        |
| `ErrInvalidArgs`      | args не прошли JSON Schema или превысили 32 KB                                                      | 400 с перечнем нарушенных полей          |
| `ErrMaxSteps`         | исчерпаны `max_steps` или `max_calls`                                                               | 422, признак «слишком длинный tool-цикл» |
| `ErrGuardReject`      | rail `input`/`output` вернул reject (fast-fail)                                                     | 400/403 без текста сработавшего правила  |
| `ErrGuardUnavailable` | пул ORT перегружен (>2 с) или guard недоступен (fail-closed)                                        | 503                                      |
| `ErrProvider`         | ошибка LLM/embed-провайдера; для ORT-эмбеддера — таймаут очереди                                    | 502                                      |
| `ErrNotFound`         | `Delete`/`Search` не нашли документ или индекс                                                      | 404                                      |
