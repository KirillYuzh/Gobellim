# Защита (guards)

Guard — конвейер детекторов, который проверяет ввод и результат инструментов.
Решает: разрешить, замаскировать или отклонить операцию.

## Как работает

Любой входящий текст проходит через конвейер детекторов:

```
текст → детекторы → вердикт (Allow / Mask / Reject) → текст (изменённый или исходный)
```

Каждый детектор ищет свою категорию: PII (паспорт, ИНН, СНИЛС, email, телефон),
секреты (ключи, токены), инъекции, небезопасный контент.

## Вердикты

| Вердикт  | Что происходит                                        | Когда                                     |
| -------- | ----------------------------------------------------- | ----------------------------------------- |
| `Allow`  | Текст проходит без изменений                          | Проблем не найдено                        |
| `Mask`   | PII заменяется на `[PII:EMAIL]`, `[PII:SNILS]` и т.д. | Найдены персональные данные               |
| `Reject` | Операция блокируется с ошибкой                        | Найдена инъекция или небезопасный контент |
| `Detect` | Найдено, но не блокируется (только для output-рельсы) | Инъекция в результате инструмента         |

## Рельсы (rails)

Вердикт зависит от рельсы — места, где происходит проверка:

| Рельс            | Что проверяется                        | Действие по умолчанию         |
| ---------------- | -------------------------------------- | ----------------------------- |
| `RailInput`      | Ввод пользователя (чат, поиск, ingest) | PII → mask, инъекция → reject |
| `RailToolResult` | Результат инструмента                  | Инъекция → detect, PII → mask |
| `RailOutput`     | Ответ модели пользователю              | Инъекция → detect, PII → mask |

## Конфигурация

```go
app, err := gobellim.New(ctx, gobellim.Config{
    GuardL2:      guard.L1Only(),   // без ML-слоя
    GuardMaxChars: 8000,            // лимит на проверяемый текст
    GuardWindowChars: 1024,         // размер окна сканирования
    GuardFailOpen: nil,             // пусто = fail-closed везде
})
```

## Ограничение длины (truncation)

Если текст длиннее `GuardMaxChars`, проверяется только его начало. Хвост не
инспектируется, поэтому вердикт `Mask` на обрезанном тексте невозможен: он
повышается до `Reject` — fail-closed, чтобы не вернуть неинспектированную
часть. На рельсе `RailInput` обрезанный текст всегда даёт `Reject`. На
`Reject` `Verdict.Text` использовать нельзя.

## Детекторы

L1 — детерминированные правила (регулярные выражения, контрольные суммы).
L2 — ML-модель (опционально, требует `-tags ort`).
